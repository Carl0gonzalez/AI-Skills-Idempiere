# Entrega y continuidad

Para un cierre: resultado observable; archivos o PR si existen; pruebas realmente ejecutadas; límite material o decisión pendiente. No impongas emojis, número de párrafos ni silencio durante trabajo prolongado.

Para una especificación: problema y usuario, alcance, requisitos verificables, contratos afectados, supuestos y preguntas materiales. Añade diseño, pruebas, migración y reversa según necesidad. Guarda en la ubicación acordada o en una carpeta de trabajo apropiada; no publiques en un ticket sin encargo.

Para QA: identificador de chequeo, esperado y su fuente, observado, PASA/FALLA/NO EJECUTADO, entorno/versión y evidencia. Sin datos suficientes, informa NO EJECUTADO o INCONCLUSO. Un exit 0 con pruebas omitidas no demuestra que se probó.

Para relevo, deja sólo estado actual y siguiente trabajo autorizado. Respeta las reglas del repositorio sobre crear fichas; no crees memoria ni registros persistentes de forma implícita.
