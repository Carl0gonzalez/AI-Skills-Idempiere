# Skills comunes

**Español** | [English](README.md)

Las **11 skills comunes** centralizan workflows transversales. Confirmar la release objetivo y APIs resueltas; disponer de una instrucción no demuestra soporte runtime. Reutilizar scaffold/factories y seleccionar sólo los workflows necesarios.

| Skill | Propósito |
|---|---|
| [idempiere-architecture-patterns](idempiere-architecture-patterns/SKILL.md) | Elegir el mecanismo compatible más simple y distinguir core, plugin y entorno. |
| [idempiere-plugin-quality-gate](idempiere-plugin-quality-gate/SKILL.md) | Coordinar ejecución de pruebas, cobertura y evidencia de calidad. |
| [crear-entornos-idempiere-envrc](crear-entornos-idempiere-envrc/SKILL.md) | Crear y revisar entornos direnv aislados con comprobaciones estáticas. |
| [documentar-entornos-idempiere-envrc](documentar-entornos-idempiere-envrc/SKILL.md) | Documentar el contrato operativo del .envrc real. |
| [gestionar-tareas](gestionar-tareas/SKILL.md) | Mantener un registro de tareas existente cuando se solicita explícitamente. |
| [idempiere-event-annotation](idempiere-event-annotation/SKILL.md) | Implementar delegates anotados con APIs de la versión objetivo. |
| [idempiere-rest-resource](idempiere-rest-resource/SKILL.md) | Definir contratos REST, controles de acceso y registro ResourceExtension. |
| [idempiere-window-validator](idempiere-window-validator/SKILL.md) | Interceptar acciones de ventana resolviendo todos los callbacks. |
| [idempiere-zul-form](idempiere-zul-form/SKILL.md) | Crear formularios ZUL, controllers, wiring y recursos empaquetados. |
| [idempiere-grouped-listbox](idempiere-grouped-listbox/SKILL.md) | Implementar modelos agrupados, renderers y acceso limitado a datos. |
| [idempiere-wlistbox-custom-editor](idempiere-wlistbox-custom-editor/SKILL.md) | Personalizar editores y presentación de columnas WListbox existentes. |

Las alternativas de registro de procesos/callouts/modelos permanecen en las skills versionadas de componentes/modelos para evitar instrucciones competidoras. plugin-test-developer escribe pruebas; quality-gate coordina ejecución y evidencia. Entornos/tareas son independientes de la política core.
